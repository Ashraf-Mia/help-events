# help_events

Next.js App Router app with a community-event landing page, Better Auth + MongoDB, and generated shadcn UI primitives.

## Commands

- `npm run dev` / `npm run build` / `npm run start` — npm only (`package-lock.json` is the lockfile).
- `npm run lint` — ESLint CLI. Next 16 removed `next lint`, and `next build` no longer runs ESLint.
- `npx tsc --noEmit` — standalone typecheck. `next build` also type-checks and fails the build on TS errors.
- `npm run seed:events` — upsert the sample events in `scripts/seed-events.mjs` (reads `.env`).
- `npx next typegen` — regenerate route-aware globals (`PageProps`, `LayoutProps`, `RouteContext`). They are global (no import) and generated by `next dev` / `next build`; do not hand-write or edit `next-env.d.ts`.
- No test runner or `test` script is configured.

## Page structure

- Shared site chrome lives in `src/app/(site)/layout.tsx`; the landing page is `src/app/(site)/page.tsx`.
- Landing sections are separate components under `src/components/home/`; reusable event cards live in `src/components/events/`.
- `src/lib/events.ts` reads the 6 soonest future events from MongoDB (`events` collection) with `.sort({ date: 1 }).limit(6)`.
- The events section calls `connection()` and is wrapped in `<Suspense>` so Cache Components can prerender the static shell.

## Framework config (non-default)

`next.config.ts` enables `cacheComponents`, `partialPrefetching`, and `reactCompiler`.

- `cacheComponents` makes PPR the default and data dynamic unless cached. Use `'use cache'` with `cacheLife` / `cacheTag` for cached work, and wrap `cookies()`, `headers()`, `searchParams`, and dynamic `params` reads in `<Suspense>`.
- Do not add `dynamic`, `revalidate`, `fetchCache`, `dynamicParams`, or `runtime` route segment exports; they error under Cache Components. It requires the Node.js runtime.
- `partialPrefetching` requires `cacheComponents`; change them together.
- Turbopack is the default bundler. `*.css` is routed through `@tailwindcss/turbopack` in `next.config.ts`; there is no PostCSS config.
- All request APIs are async in Next 16 (`await cookies()`, `await headers()`, `await params`, `await searchParams`).

## Styling and UI

- Tailwind v4 is CSS-first: design tokens live in `src/app/globals.css` (`@theme inline` plus CSS variables). There is no `tailwind.config.*`; don't add one.
- `components.json` selects shadcn style `base-mira`, Base UI primitives (`@base-ui/react`), and hugeicons — not Radix or lucide.
- Prefer `npx shadcn add <component>` over hand-writing primitives; output goes in `src/components/ui/`.
- `src/lib/utils.ts` only re-exports `cn` from the npm `cn` package, and UI components import `cn` from `"cn"`. Don't add `clsx` / `tailwind-merge`.
- Import alias: `@/*` maps to `src/*`.

## Auth and environment

- Required env vars: `MONGODB_URI`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`. `.env*` is git-ignored; `.env` is loaded automatically.
- Server auth is `src/lib/auth.ts`; it uses MongoDB database `help-events` and is mounted at `src/app/api/auth/[...all]/route.ts`.
- `BETTER_AUTH_URL` is not `NEXT_PUBLIC_*`, so it is unavailable in browser code; `src/lib/auth-client.ts` intentionally uses a same-origin client.
- `src/lib/mongodb.ts` owns the shared Mongo client; don't instantiate another `MongoClient` in routes or components.
